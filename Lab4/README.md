# Лабораторная работа №4 — Алгоритмы сортировки

Веб-приложение, которое пошагово визуализирует алгоритмы сортировки «как для младшей школы»:
каждое чтение, сравнение и перестановка показываются на экране и пишутся в журнал.
Данные сортировки лежат в файлах (папка `Data/`), результат записывается в файл.

## Задания

| Задание | Что делается | Статус |
|---|---|---|
| **1. Внутренние сортировки** | Выбор, пузырёк, вставки, Шелл, HeapSort, QuickSort | в планах |
| **2. Внешняя сортировка** | Прямое, естественное и многопутевое слияние по файлу-лентам | ✅ реализовано |
| **3. Подсчёт слов** | Сортировка слов текста (базовый алгоритм + ABC/radix), подсчёт вхождений, замеры времени | в планах |

Каждое задание — отдельная вкладка; по мере разработки список и этот README обновляются.

Стек: **C# / ASP.NET Core Minimal API (.NET 10) + ванильный JS/CSS** — как в 3-й лабораторной,
без внешних зависимостей и CDN.

## Запуск

Нужен **.NET 10 SDK** (в репозитории лежит `global.json` с `rollForward: latestMajor` — подойдёт и новее).

### Visual Studio
1. Скопируй папку `Lab4` в корень репозитория (рядом с `Lab1`, `Lab2`, `Lab3`).

```bash
cd Lab4
dotnet run --project LabApp     # открыть http://localhost:5000

```

## Как работает внешняя сортировка (задание 2)

1. Таблица читается **из файла** в `Data/` (разделитель `;`, `,` или табуляция определяется
   автоматически; `TXT` — одна строка = одна запись; количество столбцов любое).
2. Пользователь выбирает метод сортировки, ключевой атрибут и порядок (▲/▼).
3. Сортировка выполняется «внешне»: записи живут на файле-лентах (`TapeFile` — только
   последовательное чтение курсором и дозапись в конец), в памяти держится **2 значения**
   (для прямого и естественного слияния) или **до 4 значений** (многопутевое).
4. Стратегия возвращает **трассировку**: снимки всех лент на каждом шаге, что лежит в памяти,
   простое объяснение и строку журнала (каждое сравнение и каждая перестановка).
5. Фронтенд проигрывает трассировку с задержкой, которую задаёт пользователь (ползунок 50–1500 мс);
   доступны кнопки Запустить/Пауза, Шаг, ⇥ В конец, Назад, Сброс (у завершённой сортировки
   кнопка запуска становится «Заново»).
6. Настройки (таблица, заголовок, метод, ключ, порядок) **независимы**: у каждого сочетания —
   своя сессия со своим прогрессом. Переключение туда-обратно ничего не сбрасывает; у нового
   сочетания сортировка начинается с нуля.
7. Отсортированные записи записываются в `Data/results/<таблица>_<метод>_<ключ>_<asc|desc>_<время>.csv`
   — файл можно скачать (кнопка на панели «Результат»), его содержимое показывается там же.
8. Каждая завершённая сортировка добавляется в **«Историю сортировок»**: таблица, метод,
   ключевой атрибут, порядок, итоговые проходы/сравнения/перестановки и время завершения.
   Клик по заголовку «Время» меняет порядок сортировки, ✕ удаляет запись; одинаковая
   сортировка не добавляется второй раз — у записи обновляются счётчики и время.

### Методы (по заданию — «прямое, естественное или многопутевое слияние»)

| Метод | Идея | В памяти |
|---|---|---|
| **Прямое слияние** | Разрезаем A на ленты B и C сериями длины p, сливаем обратно — серии удваиваются, пока весь файл не станет одной серией | **2 значения** |
| **Естественное слияние** | То же, но серии находим в данных готовыми (уже упорядоченные куски не режем) | **2 значения** |
| **Многопутевое слияние** | Раздаём записи по кругу на 4 ленты, сливаем все разом, каждый шаг беря минимум; серии растут в 4 раза быстрее | до **4 значений** |

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/health` | проверка живости |
| GET | `/api/tables` | список файлов-таблиц в `Data/` |
| GET | `/api/methods` | список методов сортировки |

| GET | `/api/results` | список файлов-результатов |

| GET | `/api/results/{file}` | скачать файл результата |

Пример (PowerShell): `Invoke-RestMethod -Uri http://localhost:5000/api/methods`

## Формат своих таблиц

Положи файл в `LabApp/Data/` и обнови страницу — он появится в списке:

- **CSV/TSV**: первая строка — заголовок (можно снять галочку «первая строка — заголовок»),
  разделитель `;`, `,` или табуляция, значения с кавычками `"..."` поддерживаются;
- **TXT**: одна строка — одна запись (например, список слов);
- числа можно писать и с точкой, и с запятой (`68.2`, `68,2`);
- столбец считается числовым, если все его значения парсятся как числа;
- для пошаговой визуализации — до 200 записей (защита от гигантской трассировки);
- файлы должны быть в кодировке UTF-8.

## Тесты

`dotnet test` — разбор файлов (разделители, кавычки, типы столбцов), сравнение
ключей (числа/алфавит/пустые), **все три стратегии сортируют корректно** (по возрастанию,
по убыванию, русский текст, стабильность при равных ключах), счётчики и журнал,
запись/чтение файла результата, защита от обхода пути (`../`).

## Расширяемость

- **Новый метод сортировки**: реализуй `IExternalSortStrategy` и добавь одну строку в
  `Program.cs` (`builder.Services.AddSingleton<IExternalSortStrategy, MyStrategy>();`) —
  он сразу появится в интерфейсе и в API.
- **Новый формат таблицы**: допиши чтение в `TableFileReader` — остальной код не меняется.
- **Новый ключевой атрибут**: тип значения (число/текст) определяется автоматически;
  при необходимости добавь тип в `ColumnType` и правило в `KeyComparer`.
- **Другой внешний вид/поведение шагов**: тексты шагов сосредоточены в `SortTraceBuilder` —
  фронтенд только проигрывает готовую трассировку.
